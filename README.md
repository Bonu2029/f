# NOW

**Available when you need it.**

NOW is a real-time local appointment marketplace. Customers open it, say what they
need, and see businesses with *actual* open appointment slots today — compared by
time, price, distance and rating — then book in a few taps. Businesses publish
empty slots and last-minute cancellations so unused time turns into revenue.

This repository is a working product prototype: every screen is real, the flows
run end to end, and the data model is the one a production build would ship.

```bash
npm install
npm run dev      # http://localhost:3000
```

---

## The two journeys that matter

**Customer** — land on NOW → search "nails" → filter to today → tap a time on
Luxe Nail Studio → the slot is held for five minutes while you check out →
Confirm & Pay → confirmation screen → the booking appears under Bookings.

**Business** — sign in as Luxe Nail Studio → see a 2:30 PM gap on today's
schedule → **Fill this slot** → Gel Manicure, 20% off ($60 → $48), visible within
5 miles → Publish → the opening is live in the marketplace within seconds → a
customer books it → the dashboard flips it to **BOOKED** and the revenue lands in
today's numbers and in *Revenue recovered by NOW*.

Both are exercised by the Playwright scripts used during development and both
pass; the second is the reason the product exists.

## Architecture

```
src/
  app/                    routes (App Router)
  components/
    ui/                   design-system primitives (button, modal, form, media…)
    marketplace/          business cards, deal cards, slot pills, map, search
    business/             public profile availability
    booking/              the four-step booking flow
    dashboard/            business SaaS surfaces
    admin/                platform console
    messaging/            booking-scoped chat, shared by both sides
    marketing/            landing, onboarding, legal, SEO pages
  lib/
    types.ts              domain model — mirrors the SQL schema field for field
    config.ts             platform configuration (commission, fees, flags)
    pricing.ts            every money calculation in the product
    store/                marketplace runtime: actions → reducer → selectors
    data/                 demo catalog + live availability engine
    supabase/             schema.sql, repository contract, client seam
    payments/             Stripe contract (intents, refund policy, webhooks)
```

### The marketplace runtime

The prototype runs on an in-memory store rather than mock JSON scattered through
components:

- **`store/actions.ts`** — every mutation as a typed action. Each one maps 1:1
  onto a future API call, which is why ids are generated by the caller.
- **`store/reducer.ts`** — one pure reducer. Defensive by design: booking a slot
  somebody already took is a no-op, not a crash, because the same guard has to
  hold on a server where two customers really can race.
- **`store/selectors.ts`** — read models (`SlotView`, `BusinessView`,
  `AppointmentView`, metrics). Components never touch raw tables.
- **`store/provider.tsx`** — persistence is an **action log**, not a state dump.
  Replaying the log over a freshly generated baseline restores your session, and
  the log is literally the list of API calls the session would have made.

Availability is generated **in the browser** against the real clock. That keeps
the demo alive at any hour and removes a whole class of hydration mismatches
around "now". Pages that matter for SEO render their static half on the server
and stream availability in — see `app/business/[slug]/page.tsx` next to
`components/business/business-availability.tsx`.

### Money

Commission is defined once, in `lib/config.ts`, and applied once, in
`lib/pricing.ts`:

```ts
priceBooking(subtotalCents, business, settings)
// → { subtotal, service_fee, total, commission_bps, commission, payout }
```

Nothing else in the codebase knows the take rate. A per-business override and a
reduced Pro rate are both supported, the admin console edits the platform value
live, and every appointment **snapshots** the rate it was booked at — rates
change, historical accounting doesn't.

Defaults: 12% marketplace commission, $1.49 + 4% customer service fee, NOW
Business Pro at $39/month with a 9% rate.

### Availability & atomic booking

A slot carries `status: available | held | booked | expired | blocked`.
Checkout **holds** it for five minutes; the hold expires back into inventory on
its own. Booking re-checks the status and refuses politely if it has gone:

> That appointment was just booked. Here are the next closest times.

`supabase/schema.sql` implements the same rule in Postgres with `select … for
update` inside `book_slot()`, so the guarantee survives real concurrency.

## Backend integration

Nothing is faked as "connected". Two seams are prepared and clearly labelled:

**Supabase** — `lib/supabase/schema.sql` is the complete target schema: tables
matching `lib/types.ts` one-for-one, enums, indexes (PostGIS for distance,
trigram for search), an atomic `book_slot()` RPC, a `search_availability()` read
model, and **Row Level Security on every table** — a business reaches only its
own bookings, customers, staff, payouts and analytics; a customer reaches only
their own data; admin routes are explicit. `lib/supabase/repository.ts` is the
interface the UI would consume.

**Stripe** — `lib/payments/stripe.ts` models Connect destination charges:
`buildCheckoutIntent()` derives `application_fee_amount` from platform settings,
`planRefund()` encodes the cancellation policy, and the webhook set is listed.
The server-side calls throw with an explanatory message rather than pretending.
No card data is collected anywhere in the UI.

Calendar integrations (Google, Square, Fresha, Vagaro, Booksy, Mindbody,
Calendly, Apple) are listed on `/integrations` and marked **Coming soon**,
because they are. What does work today is `.ics` export from any booking.

## Product decisions worth knowing

- **No photography.** Using stock images of salons would imply real businesses
  participate. Every business, service and staff member gets a deterministic
  colourway from `components/ui/media.tsx` instead — instant, offline, and
  readable as a designed placeholder. Swapping in real media is one component.
- **Reviews require a completed booking.** Enforced in the reducer *and* in the
  RLS insert policy. That is what the "Verified booking" badge means.
- **Verification is a status system, not a claim.** Only fictional demo
  businesses show a verified badge, and the onboarding flow says so.
- **Location is never required.** Denying the permission prompt falls straight
  through to neighbourhood or manual entry, and nothing stops working.
- **No login to explore.** Search, filters, profiles and prices all work signed
  out. The account is created at the moment of booking.
- **Legal pages are labelled placeholders** needing professional review, not
  invented legal advice.

## Accessibility & platform

Semantic landmarks, a skip link, visible branded focus rings, 44px tap targets,
labelled controls, `aria-pressed`/`aria-current` state, and a modal that traps
focus, restores it on close, closes on Escape and locks background scroll.
`prefers-reduced-motion` disables animation globally.

Mobile-first throughout: bottom tab bar, bottom sheets, sticky CTAs, snap rails,
and iPhone safe-area insets. Installable as a PWA via
`public/manifest.webmanifest`.
